## ADR-001：使用 MCP 低成本视频管线

- 决策：Edge TTS + 本地 FFmpeg，不用付费生成式视频。
- 理由：产品演示要准确展示真实界面，且 0 积分。
- 影响：静态分镜+平移缩放，适合快速出样片。

## ADR-002：真实产品截图与真实使用结果

- 决策：所有样片使用公开官网截图/图片，不虚构功能。
- 理由：避免客户认为样片造假；也便于后续正式合作。
- 影响：产品改版后需重新抓取素材。

## ADR-004：结尾放邮箱，不放微信和二维码

## ADR-008：Day 1 只发 4 个新客户，每位配对应品类样片

- 决策：刘春霖已发；Day 1 只发 zCAD、myPip、AgentValley、巧思工具箱。

## ADR-009：X/PH/V2EX 首触不直接发 1080p 大文件

- 决策：首触用 720p 预览；1080p 留到对方回复后。
- 理由：降低被平台压缩/拦截的概率，也避免完整版被白嫖。
- 影响：首触更轻，后续需要准备完整版链接或附件。

## ADR-010：从“追赛道”改为“追明确需求”

- 背景：用户原先通过找潜在客户和短视频平台流量判断 AI 视频能否赚钱；该方式把行业热度误当成可成交需求。
- 选项：
  1. 继续做泛化 AI 短剧内容并等流量；
  2. 找公开明确需求、有预算和联系路径的买方；
  3. 只做市场报告，不接触客户。
- 决定：采用方案 2。优先公开任务、招聘、外包需求和真实项目表达，先验证能否交易。
- 理由：买方已说出交付物和痛点时，验证成本更低；比盲猜客户更接近收入。
- 影响：项目重点从“作品数量”转向“线索质量、样片匹配度、报价和回款”。
- 回滚：若 20 条合格线索仍无法形成沟通，可回到产品演示或垂类内容实验。

## ADR-011：首单不做低价整季 AI 短剧

- 背景：公开市场出现 200–400 元/分钟和 60–95 集体量；精品与低端价格相差数十倍，小团队大量出清。
- 选项：
  1. 用低价抢整季承制；
  2. 只做 15–60 秒切片/剪辑/产品演示；
  3. 先做试播集和预演包。
- 决定：首选方案 2，方案 3 作为高价值第二切口；不做无付款保障的整季承诺。
- 理由：当前管线强项是静态分镜、真实产品素材、TTS、FFmpeg、剪辑和版本化；整季需要成熟 3D、角色一致性和批量返工能力。
- 影响：短期客单价可能较低，但交付风险、返工和坏账风险更可控。
- 回滚：拿到明确预算和稳定合作后，再逐步扩到单集/多集。

## ADR-012：所有外联必须人工确认

- 背景：用户希望找需求方交涉交易，但对外发送涉及真实沟通、隐私和商业承诺。
- 决定：研究、筛选和起草可以自动完成；发送私信、评论、邮件、报价、付费生成和发布必须由用户明确确认。
- 理由：遵守项目风险门控，避免群发、错误承诺、骚扰和隐私问题。
- 影响：自动化到“可发送包”为止，最后一击由用户本人完成。
## ADR-013：暂停一品威客内投标，优先低成本渠道

- 背景：用户反馈一品威客项目投标前需要开通 VIP，费用上万元；当前尚未验证客户真实性、预算和回款。
- 选项：
  1. 先付费开 VIP，抢一品威客任务；
  2. 暂停该渠道，优先 Remote-China、电鸭、V2EX、BOSS直聘/猎聘等低成本申请；
  3. 只用 Upwork/Freelancer.com 做小额国际测试。
- 决定：采用方案 2，必要时用方案 3 补充；一品威客暂时降级为市场证据和后续观察渠道。
- 理由：在没有明确客户和回款保障前，前置上万元会员费的风险过高；应先用样片和低金额申请验证真实付费意愿。
- 影响：短期少了部分国内任务来源，但避免沉没成本和为了回本而接低价单。
- 回滚：只有在出现明确客户、已确认预算和可接受回款条件后，才重新评估该平台会员投入。
## ADR-014：聚合岗位先回溯源站，再决定是否付费查看

- 背景：Remote-China D004 页面显示 2026-10-08，但原文落在智联招聘的旧岗位页，当前返回 404；搜索缓存显示原岗位发布日期为 2025-08-01。Remote-China 查看原文还需登录并消耗 1 积分。
- 决定：任何聚合站岗位先通过公司名、职位标题和公开搜索回溯源站；原站 404、日期过旧或无法确认发布主体时，不注册、不充值、不联系。
- 理由：聚合站发布日期可能是转载时间，不等同于招聘有效期；先付费查看再发现岗位过期会造成无谓成本。
- 影响：Remote-China D004 降为 C 级过期线索；优先使用智联招聘、BOSS直聘、电鸭、Upwork 等原站或可直接确认的项目入口。
- 回滚：仅当聚合站能提供原站有效链接、近期发布日期和明确反馈时间时，才重新评估小额积分。

## ADR-015：投标案例不得拿客户初稿充当自有作品

- 背景：《执光》投标要求提供符合附件制作标准的过往案例，但客户压缩包内只有剧本、初稿和资产，初稿不是投标方过往作品。
- 选项：
  1. 把客户初稿包装成自有3分钟16:9案例；
  2. 只使用真实可核验的自有案例，并说明其对应能力；
  3. 放弃投标。
- 决定：采用方案2。以16:9城市年代转场镜头段证明运镜转场能力，以9:16叙事短片样稿证明叙事后期能力；明确标注案例规格和限制。
- 理由：避免虚假案例和版权误认；投标应靠真实能力证据，而不是把客户素材冒充自有作品。
- 影响：如果客户硬性要求同规格3分钟16:9完整案例，本项目当前缺少该证据，应在投标前补做或如实说明。

## ADR-016：《心光如潮》先做10秒短镜头试片，不先承诺全片低价包干

- 背景：甲方要求3分35秒全包约1200元、两轮免费微调、强锁脸和原生动态；当前只有两张角色脸图和脚本，且工期描述存在冲突。
- 选项：
  1. 直接承诺全片并低价包干；
  2. 先做限定范围的10秒试片，确认画风、锁脸、配音和模型成本后再报正片；
  3. 放弃。
- 决定：采用方案2。试片拆成3条2–4秒短镜头，逐镜生成后剪辑，避免单条长视频跳脸；试片前不支付API费用，不对外承诺全片。
- 理由：短镜头更容易锁脸和修复；10秒试片能低成本验证甲方审美、角色资产和配音方向；低价全片在22个画面和两轮修改下返工风险过高。
- 影响：如果甲方把“试稿通过后5天交付”和“11月13日12:00前交付”同时作为硬条件，必须要求其确认优先时间或提前确认试稿。

## ADR-017：TASK-016 只做半自动发布，不做平台自动登录

- 背景：用户需要低成本小说推文内容工厂，但抖音/小红书个人号没有稳定、可直接申请且适合个人创作者的公开发布 API；浏览器自动化和 Cookie 保存会引入账号风控与维护风险。
- 选项：
  1. 做全自动发布；
  2. 只生成内容、封面、文案和发布包，人工上传；
  3. 只做手动脚本，不做程序。
- 决定：采用方案 2。程序生成发布包并打开官方创作中心，最后一步由用户人工确认和上传。
- 理由：手工上传 3–5 条/周只需要约 10–20 分钟；自动发布的收益不足以抵消风控、登录失效和平台改版成本。
- 影响：程序不保存平台密码或 Cookie，不自动评论、私信或发布；后续如拿到企业资质，再单独评估官方发布适配器。
- 回滚：只有出现明确企业资质和可验证官方发布权限时，才增加可选发布适配器。

## ADR-018：TASK-016 使用独立即梦-only MCP

- 背景：现有 MCP 启动器同时注册 Kling 和 Seedream/Seedance 工具；用户明确要求只调用即梦 API。
- 决定：新增 `jimeng_mcp/server.py`，只注册 Seedream/Seedance 六个工具，不导入 `kling_image_mcp.server` 或 `kling_image_mcp.kling`。
- 理由：从入口层面隔离 Kling，避免误调用和误读 `KLING_API_KEY`。
- 影响：现有 Kling MCP 可以保留给其他项目，但本内容工厂不会启动它。

## ADR-019：小说自动选择只从用户候选池中选

- 背景：用户希望程序自动选择小说，也保留手动选择；但未提供可合规抓取的第三方小说平台来源。
- 选项：
  1. 自动联网抓取小说平台；
  2. 建立用户候选池，按类型、关键词、优先级和状态自动选择；
  3. 只做纯手工输入。
- 决定：采用方案 2。候选必须由用户录入并标记自有或已授权。
- 理由：避免未经授权的平台抓取和版权风险，同时保留自动筛选能力。
- 影响：自动选择的覆盖范围取决于用户候选池；后续若要联网发现小说，需要单独接入有授权的来源并记录许可。

## ADR-020：待审项目在人工接受前禁止付费生成

- 背景：自动创建项目后仍需用户决定是否采用，避免程序自动选中不合适的小说并产生 API 成本。
- 决定：自动项目创建为 `pending_approval`，`decision=pending`；只有接受后才允许确认即梦生成。
- 理由：把选题决策权保留给用户，并防止误扣费。
- 影响：Dry-run 可以查看成本；确认生成会被阻止直到项目被接受。

## ADR-021：安装 eternityspring/shuohao-skills 短剧技能集

- 背景：用户要求安装 GitHub 上的 `entrnityspring/shuohao-skills`；核实后真实账号为 `eternityspring`，原拼写不存在。
- 来源：https://github.com/eternityspring/shuohao-skills
- 版本：`main` 提交 `8af10e0ea1a550e4575666884f4deef780bf38ff`（2026-11-09）
- 许可证：Apache-2.0。
- 决定：安装 7 个技能到 `C:\Users\陈楷浩\.codex\skills`：`character-refs`、`novel-art`、`novel-characters`、`novel-outline`、`novel-script`、`novel-staging`、`novel-storyboard`。
- 审查：安装前静态检查脚本；7 个自带自测共 1,559 项断言全部通过；安装后 113 个文件 SHA-256 与审查源一致。
- 风险：`character-refs` 在用户明确执行出图时会调用本机 Codex、OpenAI API 或用户配置的自定义命令，可能消耗订阅额度或 API 费用；其余技能只做本地结构化处理并输出 JSON、Markdown、HTML。
- 影响：技能在下一轮对话中进入可用技能列表；未执行付费生成，未运行仓库根目录安装脚本。

## ADR-022：本机豆包通过技能上传 + Windows UI 自动化桥接

- 背景：豆包桌面端提供“上传技能”和视频生成入口，但当前没有可直接调用的官方个人技能 API。
- 选项：
  1. 仅粘贴长提示词，不真正加载技能；
  2. 制作单一豆包技能包并上传，再用 Windows UI 自动化操作客户端；
  3. 等待或申请外部 API。
- 决定：采用方案 2。创建 `shuohao-short-drama` 单文件技能包，包含顶层 SKILL.md 和原始技能说明；通过豆包“上传技能”导入，再由 UI 自动化完成对话、确认和视频生成。
- 理由：已实际验证豆包读取技能并能生成可播放视频；不依赖未提供的 API 或密钥。
- 影响：该桥接依赖豆包桌面端版本和界面结构，后续 UI 改版可能失效；视频生成消耗豆包免费额度或其他平台额度，提交前仍需参数确认。


## ADR-023：豆包免费额度通过网站任务桥接入，不由后端保存登录态

- 背景：豆包个人桌面端没有可直接调用的个人技能/视频 API，登录态和界面结构不稳定。
- 决定：网站只生成 5×10 秒计划、提示词和片段目录，导入本地 MP4 后完成拼接、字幕和混音；豆包操作由本机 Computer Use 执行。
- 理由：避免把账号 Cookie 或登录态写入业务后端，同时保留可审计的任务计划和片段资产。
- 影响：豆包界面改版可能影响自动化；片段导入和成片渲染可独立复用。

## ADR-024：免费额度不足时保留付费门控，使用本地收尾镜头完成 50 秒

- 背景：本次豆包免费额度在第 4 条镜头后耗尽，用户明确要求 50 秒成片且不使用付费额度。
- 决定：前 4 段保留豆包生成，第 5 段使用第 4 段画面、标题排版和低频环境音做本地后期收尾；不购买订阅、不切换付费 API。
- 理由：仍能交付完整 50 秒结构，同时保持“只使用豆包免费额度”的边界。
- 影响：第 5 段不是豆包生成镜头；若需要纯豆包 5 镜头版本，需次日免费额度恢复后重新生成并重渲染。

## ADR-025：TASK-023 GitHub 趋势使用本地快照而非伪造历史曲线

- 背景：GitHub REST 不提供仓库历史 Star 曲线，单次搜索只能得到当前累计值。
- 决定：首次扫描只保存基线；之后使用距离当前 12–36 小时的最近快照换算 24 小时 Star 增量，并在数据不足时显示“增长待确认”。
- 影响：新安装后的第一份榜单按相关性和当前质量排序；历史趋势需要持续运行后逐步形成。

## ADR-026：TASK-023 雷达只做发现与评估，不自动安装第三方 Skill

- 背景：GitHub 仓库可能包含安装脚本、付费 API、Cookie 或高风险依赖，自动安装会扩大权限和数据风险。
- 决定：程序只保存公开元数据、README/SKILL 摘要、许可证和链接；用户自行打开原链接并决定是否试用。
- 影响：雷达能降低信息搜集成本，但不会替用户执行第三方代码；后续如增加安装能力，需要独立的安全审查和人工确认。

## ADR-027：按镜头拆分旁白、音乐和环境音，不采用整片单轨配乐

- 背景：短剧不同镜头需要不同的紧张度、环境声和音效；整片一首 BGM 会削弱叙事节奏。
- 决定：声音计划以镜头为最小单位，每个镜头分别记录 voice、music 和 sfx 线索，再按时间线混音。
- 理由：可以独立控制旁白音量、音乐淡入淡出、音效起点和不同场景的音乐风格。
- 影响：声音工程文件增多，但可以复用、替换和审计；最终成片仍自动进入发布成片库。

## ADR-028：声音 Provider 采用本地优先、云端可选、失败显式回退

- 背景：MeloTTS、ACE-Step 和 Freesound 的安装状态、网络和额度可能变化。
- 决定：默认优先本地 MeloTTS/ACE-Step；Freesound 仅使用用户配置的 Key；失败时回退 Edge TTS 和本地合成音，禁止伪造成功。
- 理由：保证网站始终可渲染，同时保留实际来源、许可证和回退警告。
- 影响：回退版可用于流程验证，但正式发布前应检查 manifest，确认实际使用的 Provider 和授权。

## ADR-027：TASK-025 有条件自动安装第三方 Skill

- 背景：用户明确表示没有时间逐项挑选，并授权程序直接安装值得使用的 Skill。
- 决定：每日最多自动安装 1 个新 Skill；只接受评分 ≥70、许可证白名单、根目录 `SKILL.md`、未超文件/体积限制且通过 ZIP 安全检查和危险模式扫描的项目。
- 执行边界：安装只复制文件，不执行仓库中的任何脚本；含脚本的 Skill 附带 `RADAR_INSTALL_NOTICE.md`。
- 影响：自动化程度提高，但静态扫描不能替代完整安全审计；用户首次调用含脚本 Skill 时仍需复核依赖、权限和外部服务。
