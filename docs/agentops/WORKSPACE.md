# AI 短剧工作台：固定三条工作流

> 最后更新：2026-11-15
> 用途：这是当前对话后续处理“每日项目、GitHub 情报、豆包出片”的长期入口说明。用户不需要反复解释项目结构。

## 一句话目标

每天先选出值得做的视频项目，再用 GitHub 情报降低工具和方法成本，最后用豆包 Skill 把确认后的项目做成视频。

## 三个固定分区

| 分区 | 解决的问题 | 默认入口 | 主要产物 |
|---|---|---|---|
| 每日视频项目 | 今天做什么、项目推进到哪一步 | `http://127.0.0.1:8765/#daily` | 项目、脚本、分镜、素材、发布包、发布记录 |
| GitHub 情报 | 用什么新工具/方法降本 | `http://127.0.0.1:8765/#radar` | 雷达精选、日报、安全安装记录 |
| 豆包制作 Skill | 怎么用豆包把项目做出来 | `http://127.0.0.1:8765/#doubao` | IP 简报、分镜图、分集视频、初剪文件 |

总览页：`http://127.0.0.1:8765/`

## 固定触发口令

### 1. “做今天的视频项目”

默认执行：

1. 读取现有候选池、项目队列和最近发布记录。
2. 筛选最多 3 个适合竖屏/短剧的项目方向，说明选择理由、授权风险和预计成本。
3. 默认只创建待审项目，生成脚本和分镜；不调用付费 API。
4. 给出一个最推荐项目，等待用户接受后再继续。

### 2. “扫描 GitHub 情报”

默认执行：

1. 触发雷达扫描或读取当天已有精选。
2. 只汇报最值得试的 3 项，必须写清许可证、风险、降本价值和可执行下一步。
3. 只允许自动安装通过静态安全检查的标准 Skill；每天最多安装 1 个。
4. 不因扫描自动产生付费调用，不执行第三方仓库脚本。

### 3. “用豆包制作视频”

默认执行：

1. 读取当前项目、`SKILL.md` 和项目已有分镜。
2. 依次使用：Phase 1 创作 → Phase 1.5 分镜图 → Phase 2 按集出片。
3. 出片前必须查看 `--dry-run`、模型版本、预计积分和已有片段，禁止直接批量消耗额度。
4. 先生成一集或一组镜头验证，确认后再继续。
5. 产出片段按 `shot-01.mp4` 等标准命名，导入项目库做声音、字幕、拼接和发布包。

## 当前默认制作策略

- 平台默认：竖屏 9:16，1080×1920，30fps。
- 单条默认：50–60 秒，优先 5–6 个 10 秒镜头。
- 豆包优先使用免费额度；付费 API 必须单独确认。
- 每个镜头只安排一个主要动作，先保角色、场景和道具连续性。
- 发布包、字幕、AI 标识和版权状态随项目保存，不能只留在聊天里。

## 与用户对话的固定方式

- 用户只说“继续”时：先判断当前属于哪个分区，再读取 `STATE.md` 和对应项目文件，不凭空猜。
- 每次开始先回报“当前分区 + 今天的目标 + 是否会调用外部服务”。
- 涉及付费生成、公开发布、外发消息、安装未审核代码时，先说明风险和预计成本，等待确认。
- 每次阶段完成后更新 `STATE.md`；重要产物路径写入 `EVIDENCE.md`。
